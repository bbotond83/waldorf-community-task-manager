# Team Allocation

## Staffing and Ownership

A Bolt is one build pass over a piece of work, ending in a verifiable result. Team Formation was skipped in classic scope; the user selected Construction from this session, with `solo` ownership and recorded unit-first serial execution. All three Bolts are executed by **aidlc-developer-agent (AI)**. This does not create separate human teams or authorize parallel writes. Stage-declared reviewers remain independent where required by the workflow.

| Bolt / Unit | Implementation owner | Supporting expertise | Verification responsibility |
| --- | --- | --- | --- |
| B1 / U1 | aidlc-developer-agent | Architect for contract/schema and migration/policy boundaries; security perspective for revocation/promotion risks | Developer layer tests and approved checkpoint command; quality engineer integrated checks later |
| B2 / U2 | aidlc-developer-agent | Architect for source/port contracts; designer for responsive states/focus | Developer projection/UI/redirect tests and checkpoint; actual browser/accessibility checks when executed |
| B3 / U3 | aidlc-developer-agent | Architect for policy-consumer parity; delivery lead for completeness | Developer retained-persona/manifest tests and checkpoint; quality engineer final integrated evidence |

These assignments identify responsibility, not additional unsolicited delegation. Use each stage's declared execution mode and reviewer requirements. The human owns approval decisions; initial implementation-plan approval, protected verification command and mandatory failure checkpoints are not waived. No Construction autonomy choice has been inferred.

## Shared-file Responsibility

| Surface | U1 owns | U2 owns | U3 owns |
| --- | --- | --- | --- |
| src/access and SQL migration | Current-role types/policy, grant conversion/version/audit and matching SQL policies/constraint | Consumer behavior only | Migrated fixture/workflow assertions only |
| Application shared contracts/authorization/facades | Current role and session declarations, authorization rows, shared policy consumer gates | Teacher source/projection/result fields and teacher facade | Retained workflow orchestration and final executable contract references |
| Runtime catalog/session/composition | Four current profiles, mapping/session/version resolution and removed-cookie recovery | Teacher adapter binding and current teacher navigation destination | Retained workflow fixture wiring and remaining catalog-reference assertions |
| Web | Shared persona/session gates required by current role semantics | Teacher pages/components and old GET-only redirects | Remaining parent/admin workflow presentation and current-role copy |
| Directory/Coordination | Role-check adaptations for approved policy | Tracking port uses authoritative source, not writable business ownership | Retained core workflow/preservation assertions |
| Imports/Notifications/Privacy | Current authorization boundary adaptations | No new lifecycle owner | Retained workflow adaptation and archive-owner metadata |
| tests/verification fixtures/manifests | Tests local to U1 and shared policy case corpus | Tests local to U2 and teacher source/route fixtures | Tests local to U3 and final manifest/scenario inventory/integrity |

Use serial integration on `feature/simplify-user-roles`; do not rewrite earlier units' owned policy/contracts to satisfy later consumers. Where an exact function moves or a file must be renamed, its implementing unit records the owning change and downstream consumers adapt through the approved contract. Tests belong to the change that needs them, rather than waiting for final cleanup. Preserve other contributors' edits and the local-only next-env.d.ts change.

## Handoffs and Sources

U1 supplies C1/C2/C5 to U2/U3; U2 supplies C3/C4 to U3. Verified unit checkpoints precede dependents. Build and Test consolidates current evidence across all completed units. Historical audit records and old stage outputs remain accurate; current catalogs/fixtures use English Kindergarten teacher naming and Hungarian UI copy.
