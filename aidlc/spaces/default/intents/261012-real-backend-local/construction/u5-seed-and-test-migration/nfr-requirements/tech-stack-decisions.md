# Technology Decisions: U5 Seed and test migration

Existing stack kept (Next.js 16, React, strict TypeScript, Node 24, Vitest, Node test runner, Playwright, ESLint, Prettier) with U1's local stack and the functions of U2 to U4. No new library is added; one dependency update is a first task. Source: the answers in `nfr-requirements-questions.md` and U1 to U4's decisions.

| ID | Decision | Rationale | Check |
|---|---|---|---|
| NFR2.30 | Seed and reset are server-side scripts in `scripts/db/` (like `start`, `migrate` and `worker`), run through new `package.json` commands (small seed, 30-family seed, reset); the seed uses the sign-in service's admin interface to create accounts directly and database functions or inserts for the rest, in one transaction per schema | One mechanism with U1's scripts; accounts need the sign-in service, records need a transaction (NFR3.19) | Seed, reset and failure-injection tests (NFR3.18, NFR3.19) |
| NFR2.31 | The seed's data is defined once in a data module (small set, and the 30-family set as a larger deterministic generator of it) with fixed uuids; the seed file holds the test passwords | Tests can name records; one place to read | Idempotence test (NFR3.18) |
| NFR2.32 | The local-only guard is one shared function used by seed, reset and any future destructive script; it checks the loopback address and asks the database to identify itself as the local stack | A single test target for the refusal (NFR1.63) | The refusal tests |
| NFR2.33 | Test isolation uses U1's per-worker schemas (`worker_1` to `worker_4`); the browser configuration gives each of the three browsers its own schema, port and server, and resets the schema to the small seed before every test file; the three browsers run one after another (answer to Q1) | Predictable results over speed; the schemas already exist | The configuration test and three full runs in a row (NFR3.20) |
| NFR2.34 | The synthetic composition, fixtures, reset endpoint, per-browser copies, profile picker, `scenario` hooks, the four synthetic adapters (`src/parent-web`, `src/admin-core`, `src/admin-advanced`, `src/teacher-web`) and `src/teacher-tracking` are deleted; `APP_RUNTIME_MODE=synthetic` and its CI uses disappear, so CI builds and tests against the stack | FR10.1 and FR2.6 | The deletion and route tests (NFR1.67, NFR2.29) |
| NFR2.35 | The audit purge is a new forward-only migration after U4's last (`20261044_...`), one security-definer function with a pinned search path and an elevated-function catalogue entry; housekeeping and the seed and reset commands call it | Smallest mechanism for the 365-day rule; no scheduler needed locally | NFR1.68 tests |
| NFR2.36 | The first task updates `zod` (to 4.6.7 or later) and the packages behind `undici` in the lockfile and package manifest; no other dependency changes | Clears the high advisories so `npm audit --audit-level=high` passes | The dependency audit (NFR1.70) |
| NFR2.37 | Checks before the unit completes: strict type check, lint, format check, all tests, production build, start smoke, the critical browser flows with the accessibility scan, secret and privacy scans, dependency audit (high and critical block), and at least 80% line, branch and function coverage across all production source; `package.json` lint and format lists and U3's scope-guard test are updated for every folder U5 adds or removes | Team practice and NFR2 | The verification chain of the unit |
| NFR2.38 | Documents are updated in the same change: the English README (prerequisites and the start, stop, seed, reset commands), the Hungarian testing guide (`HASZNALATI_UTMUTATO_HU.md`: real sign-in, invitations, password reset, several people at once) and a short report on the real workbook in git history and the known limits | FR1.5, FR11.2, FR12.1 | A review of the three documents and a test that the README lists each command |
| NFR8.4 | Identifiers, schema names, scripts, logs and technical documents are English; seeded visible text and the guide are Hungarian | NFR8 | Copy checks |
