### Summary

U5's changes do not break what U1 promises. The trigger still refuses every update, every delete of a recent row and every delete outside audit_purge(); audit_purge() is limited to the system caller and the write function and idempotency storage are untouched. Runtime configuration still fails fast with no synthetic fallback. CI still starts the stack, runs the database tests and stops it, and its test was updated to match. The source manifest still covers the changed U1 files (`scripts/db/` and the CI and verification files); the new migration and seed tests belong to U5. The remaining points are documentation drift, a purge gate that depends on revoked grants, and a reset guard that could be tighter.
