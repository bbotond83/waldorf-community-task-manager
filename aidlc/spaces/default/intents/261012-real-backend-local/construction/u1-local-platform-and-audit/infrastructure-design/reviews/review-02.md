> R-01 Reviewer note: The four worker schemas are now named in `[api] schemas` and created by a bootstrap migration before the data API starts. The runner uses a session search path, grants are stated, and a 10-second confirmation request is defined. This removes the runtime reload that was the problem. The one deferred item is whether the CLI applies migrations before starting the data API. Deferring it to the first code-generation spike is acceptable because the failure is loud (the confirmation step names the schema) and the fallback is a restart of the data API container.

> R-02 Reviewer note: The ports are enumerated and a post-start check requires them to be reachable on 127.0.0.1 and not on other addresses. A fallback is stated. Residual gaps are listed in the new findings. Deferring the CLI bind behaviour to the spike is acceptable.

> R-03 Reviewer note: The key model now uses the CLI's well-known defaults and is consistent across the specification and CI. The public key and address go to an ignored file, and the service-role key goes to a separate ignored file read only by the tooling. The scan uses a hash allowlist, so no key values are stored in tracked files.

> R-04 Reviewer note: The concrete edits to `ci.yml`, `run-local-verification.ts`, `scan-artifacts.ts` and `package.json` are listed. Coexistence with the PostgreSQL 18 tools step is explained. The NFR2.6 deviation is recorded. The cold-pull start time is reported only and the step has a 10-minute timeout. A wording problem remains in the `ci.yml` row (see new findings).

> R-05 Reviewer note: The disabled services are listed with config keys, and the key names are flagged for confirmation in the spike. The mail catcher's enable key and a check that only the wanted services run are still not stated (see new findings).

> R-06 Reviewer note: NFR4.5, NFR1.12, NFR1.13, NFR2.7, NFR3.4, NFR6.1 and NFR6.2 are now mapped. The index statement exists in "Indexes and Pinning Checks".

> R-07 Reviewer note: The CLI is pinned as an exact development dependency, and the images are tied to the CLI release. The cold-pull handling is stated.
