# Entities: U1 Local platform and audit

The three records U1 owns, plus the conventions every table in the schema follows. Source: `components.md` (PrivacyAudit, ApplicationKernel), requirements FR3.1, FR3.2, FR3.5, FR3.6, and the confirmed answers in `functional-design-questions.md` (Q1, Q2, Q4).

```yaml
conventions:
  primary_key: "every table has a primary key of logical type uuid, generated by the database; no readable text ids"
  scope_columns: "every table that holds group- or organization-owned data carries its scope (organization and, where it applies, group) as columns, so row-level rules can read them without joins to other blocks"
  version: "every mutable record carries an integer version that increases by one on each accepted update"
  timestamps: "created_at and updated_at in UTC on every mutable record"
entities:
  - name: AuditEvent
    owner: PrivacyAudit
    description: "One append-only record of a role change, approval, import or lifecycle action"
    attributes:
      - { name: id, type: uuid, required: true, unique: true, default: "database-generated" }
      - { name: actor_account_id, type: uuid, required: true, references: "Identity.Account (unconstrained reference)" }
      - { name: actor_role, type: text, required: true, allowed: [parent, teacher, group_admin, super_admin, system] }
      - { name: action, type: text, required: true, allowed: [role.grant, role.revoke, role.first_super_admin, approval.approve, approval.reject, import.commit, lifecycle.anonymize, lifecycle.delete, lifecycle.hold_place, lifecycle.hold_release] }
      - { name: target_type, type: text, required: true }
      - { name: target_id, type: uuid, required: true }
      - { name: organization_id, type: uuid, required: true }
      - { name: group_id, type: uuid, required: false }
      - { name: outcome, type: text, required: true, allowed: [success, denied], constraints: "an error rolls back the event with the change, so no failed outcome is stored" }
      - { name: details, type: text, required: false, max: 500, constraints: "never holds personal data" }
      - { name: occurred_at, type: timestamp, required: true, default: "now (UTC)" }
    constraints:
      - "append-only: no update and no delete by any application role"
      - "written in the same transaction as the change it describes"
    relationships:
      - { to: "Identity.Account", cardinality: "many to one", direction: "AuditEvent refers to Account (typed unconstrained reference)" }
  - name: IdempotencyRecord
    owner: ApplicationKernel
    description: "The stored result of an operation, keyed by a caller-supplied key, so a repeated submission returns the same result instead of acting again"
    attributes:
      - { name: id, type: uuid, required: true, unique: true, default: "database-generated" }
      - { name: account_id, type: uuid, required: true, references: "Identity.Account (unconstrained reference)" }
      - { name: operation, type: text, required: true }
      - { name: idempotency_key, type: text, required: true, max: 200 }
      - { name: request_fingerprint, type: text, required: true, constraints: "hash of the request, never the request itself" }
      - { name: result_state, type: text, required: true, allowed: [success, validation, denied, conflict, terminal], constraints: "retryable is never stored" }
      - { name: result_reference, type: uuid, required: false }
      - { name: created_at, type: timestamp, required: true, default: "now (UTC)" }
      - { name: expires_at, type: timestamp, required: true, default: "created_at plus 24 hours" }
    constraints:
      - "unique on (account_id, operation, idempotency_key)"
      - "stores the outcome state and a reference, never request bodies or personal data"
    relationships:
      - { to: "Identity.Account", cardinality: "many to one", direction: "IdempotencyRecord refers to Account (typed unconstrained reference)" }
  - name: LifecycleHold
    owner: PrivacyAudit
    description: "A hold that stops a record from being anonymized or deleted by the lifecycle process until it is released"
    attributes:
      - { name: id, type: uuid, required: true, unique: true, default: "database-generated" }
      - { name: target_type, type: text, required: true }
      - { name: target_id, type: uuid, required: true }
      - { name: organization_id, type: uuid, required: true }
      - { name: reason, type: text, required: true, max: 300, constraints: "never holds personal data" }
      - { name: placed_by_account_id, type: uuid, required: true, references: "Identity.Account (unconstrained reference)" }
      - { name: placed_at, type: timestamp, required: true, default: "now (UTC)" }
      - { name: released_at, type: timestamp, required: false }
      - { name: version, type: integer, required: true, default: 1 }
      - { name: updated_at, type: timestamp, required: true, default: "now (UTC)" }
    constraints:
      - "at most one open hold (released_at empty) per (target_type, target_id)"
    relationships:
      - { to: "Identity.Account", cardinality: "many to one", direction: "LifecycleHold refers to Account (typed unconstrained reference)" }
```

## Summary

U1 owns three records. The audit log is append-only and holds no personal data. The idempotency record keeps only a hash and an outcome, for 24 hours. The lifecycle hold records why a record must not be removed yet; executing the lifecycle itself is completed in U3. Other tables arrive in U2 to U4 and follow the same conventions (uuid keys, scope columns, version numbers).

Naming against the domain design: `account_id`, `idempotency_key` and `request_fingerprint` replace the domain design's `subject_id`, `request_key` and request hash; the narrower audited-action list (BR3.2) supersedes the domain design's wider audit wording.

Not stored as entities: the runtime configuration (read from the environment at startup, see `functional-spec.md`) and worker schemas (created and reset by the tooling, see `functional-spec.md`).
