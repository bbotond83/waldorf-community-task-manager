### Summary

The differential holds. The U5 changes remove only the synthetic path and leave what U3 promises in place. Family, admin reach and teacher groups come from `resolveParentAccess`, `resolveAdminAccess` and `resolveTeacherAccess`, which read the signed-in account's Parent link and role grants from the database, with no constants (BR32.2). The removed scenario selects only fed the `scenario` payload field of the synthetic adapters. The real assignment form (family selector), the task and record forms, the import, reminder and lifecycle actions, and the grant revocation all remain.

The swap action now requires a chosen counterpart as `<assignment>:<version>`, and the page always asks the database for the partner list. This matches BR31.4, where the parent picks the target from `swap.candidates`, and BR32.7. The audit purge migration keeps the table append-only, so every update is refused and a delete is refused except inside `audit_purge()` for rows older than 365 days. `audit_purge()` is executable only by the system caller, and the append-only tests in `tests/database/audit.test.ts` and `reset.test.ts` still apply. Contact and note privacy through the database policies is untouched.

Two minor record-keeping points remain, with no architectural defect.
