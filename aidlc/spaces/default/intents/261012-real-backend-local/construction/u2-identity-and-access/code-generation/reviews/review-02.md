> R-01 Reviewer note: acceptInvitation now deletes the new sign-in user only after invitation_release answered "released" for its own reservation, which proves the accept never committed; any other or missing answer keeps the user and writes follow_up_failed. The operator command deletes only when a fresh connection answers that no Account exists for the id. Tests cover lookup or release unavailable, a lost accept answer, and a dropped connection after commit.

> R-02 Reviewer note: The exposure is closed in the database for direct calls: password_verification_hook counts per account under an advisory lock, so parallel attempts are serialized (the lock is taken before the count is read, and each statement sees prior commits), refuses even the right password while locked, does not record while locked, and is covered by a real-stack test of direct calls including 14 parallel attempts. password_requirements = letters_digits is now set. Residual points are listed under new findings (response text, worker schemas).

### Summary

All four Major findings of iteration 1 are fixed with real-stack evidence: compensation can no longer delete a user with an Account, direct password attempts are now locked by the sign-in service's own hook with an atomic count, the reset answer time no longer depends on the address, and sessions are renewed per request in the proxy. Only Minor points remain (hook reject text, the public-schema-only wiring, proxy cookie defaults, and documentation drift), so the unit is READY.
