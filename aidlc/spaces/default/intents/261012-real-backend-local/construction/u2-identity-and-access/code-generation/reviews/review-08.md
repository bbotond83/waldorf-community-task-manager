### Summary

Nothing from unit u5 breaks or weakens what this unit promises. The real session path is intact: `currentSession` reads the cookie pair and calls `resolveSession`, `productionRequest` returns signed-out or unavailable unless the session is active, and `proxy.ts` still renews or clears cookies. The invitation page returns a uniform "not valid" answer for malformed, unknown or unavailable tokens. The service-role key is read only by `src/identity/admin-runtime.ts`, which is marked server-only and hands it to `admin-client.ts` (as designed). Operator scripts under `scripts/db` also read it, but those are not in the browser bundle. In CI the key is masked and exported only to the Validate job. The SBOM job carries build-only placeholders and no key. The seed accounts script is guarded to the local stack and does not log passwords. The only findings are two documentation or manifest drifts and one robustness gap in the housekeeping change.
