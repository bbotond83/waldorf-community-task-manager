> R-01 Reviewer note: `20261021_identity_invitation_stale_reservation.sql` adds `invitation_release_stale()` and calls it first in revoke, resend, create, reserve and housekeeping. Reserve now releases before the expiry check, so an expired stale reservation becomes an expired pending invitation that create can replace. A fresh reservation (under 2 minutes) still blocks. A slow earlier holder cannot overwrite: `invitation_accept` still requires a fresh reservation and its row lock makes the release skip an accepted row. Tests cover stale revoke, stale resend and create after expiry.

> R-02 Reviewer note: `20261022_identity_email_change_guard.sql` puts a before-update trigger on `auth.users` that refuses any change to `email` or `email_change` unless a transaction-local setting allows it. Unchanged-email updates (ban, password, last sign-in) do not fire it. `identity-email-change.test.ts` runs against the real sign-in service: a direct change is refused, an invitee's address stays free, reset still works and a password change still works. The test is in the `test:database:identity` script. Two residual limits are listed under New findings.

> R-03 Reviewer note: `unit-test-instructions.md` now lists commands that match files on disk: the glob over `src/identity/*.test.ts`, `npm run test:database:identity` (which includes the hook and email-change tests), the hook test on its own, the bundle test, and the `tests/integration/*` screen, action, runtime and proxy tests. One stale phrase remains (see New findings).

> R-04 Reviewer note: Housekeeping now deletes attempt rows only after 30 minutes, the lock function's look-back, so a run cannot shorten an active lock. A test runs housekeeping inside a lock.

> R-05 Reviewer note: `20261023_identity_ban_reconcile.sql` adds `identity_ban_mismatches()` (service-role only, limit 100). `reconcileAccountBans` repeats the ban (plus session removal) or the ban-lift, and the sign-in housekeeping callback runs it. The function is in `ADMIN_FUNCTIONS` and the catalogue test. A race between the list and an admin change is harmless because the database refuses a deactivated account whatever the ban says, and the next pass corrects it.

> R-06 Reviewer note: The sign-in service client returns a distinct `rate_limited` outcome. Sign-in records no attempt and shows its own Hungarian message. Refresh, session and reset treat it as transient. The admin client still maps 429 to unavailable, which is fine for server-side calls that have no message to show.

> R-07 Reviewer note: A password the sign-in service refuses now returns `PASSWORD_REJECTED`, and the screen tells the person a new link is needed. The related unavailable-path gap is listed under New findings.
