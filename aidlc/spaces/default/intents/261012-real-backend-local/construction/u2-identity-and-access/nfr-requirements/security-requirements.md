# Security Requirements: U2 Identity and access

Source: NFR1 and NFR5 of the requirements, rules BR2.1 to BR2.23, U1's security requirements, and the first reviews of the functional design.

| ID | Requirement | Check |
|---|---|---|
| NFR1.1 | A request is accepted by the database only for an active session of an active account (BR2.6); signed-out, expired (past 30 days idle), deactivated and never-registered tokens read and write nothing | Database tests with each of the four token states for every table and every named function |
| NFR1.2 | Every policy is tested per role and read path: parent, kindergarten_teacher, group admin of the same group, group admin of another group, super admin, account with no grant, deactivated account, signed-out session, for every table that exists, in the default schema and a worker schema (BR2.15) | The policy test list; a catalogue test fails when a table with row-level security has no case |
| NFR1.3 | Every security-definer function is on the authoritative list, pins its search path, is not executable by anon, and checks its caller (BR2.16) | A catalogue test over all security-definer functions in the schema |
| NFR1.4 | The service-role key has no table rights anywhere in the schema and may execute only the named admin-access functions (BR2.23) | A database test lists service_role privileges and compares them with the allowed list |
| NFR1.5 | The service-role key is read only by the server-only admin module and never reaches client code or browser output (BR2.23, U1 NFR1.4 as amended) | A bundle scan of the production build for the key name, value and the module path; U1's config check updated and tested |
| NFR1.6 | Passwords, tokens, invitation links and reset links never appear in logs, audit events, error messages, URLs of redirects after submit, or test output | Output and log tests with fake secrets for every server action and every command |
| NFR1.7 | The session cookie is httpOnly, sameSite lax and secure whenever the site is served over https (BR2.5) | A unit test of the function that builds the cookie options for an http and an https origin, plus a browser test reading the httpOnly and sameSite flags over the local http origin and the secure flag in a production-mode run behind a local https origin |
| NFR1.8 | Invitation tokens are 32 random bytes, only their hash is stored, the hash column is not selectable by application roles, and a link works once (BR2.10, BR2.11) | Database tests for the column privilege, reuse, expiry, replace and concurrent double submit |
| NFR1.9 | Password rules are enforced on the server as well as on the screen (BR2.4) | Unit tests for each rule and for the 72-byte limit |
| NFR1.10 | The lockout is applied for 5 wrong passwords in 15 minutes, never reveals whether an address exists, does not extend itself while locked, and uses a keyed hash of the email (BR2.3) | Tests with a controllable clock for the count, the window, the lock, the reset by success, and unknown addresses |
| NFR1.11 | Open sign-up is closed in both configuration switches and a direct sign-up call is refused (BR2.13) | A test against the real stack calling the sign-up endpoint |
| NFR1.12 | Grant changes cannot escalate: a group admin cannot touch grants outside their group, cannot deactivate, and the last super admin cannot be removed even by two concurrent changes (BR2.14) | Database tests including a two-connection race |
| NFR1.13 | The scope probe returns only allowed, denied or not_found, and another organization's record always answers not_found (BR2.17) | Wrong-role tests per supported record type |
| NFR1.14 | The first-super-admin command never reads a password from an environment variable, a file or an argument, requires the typed target host, and removes the new user on failure (BR2.18) | Tests with a fake terminal for the prompt, the host mismatch, the existing admin, and an injected failure |
| NFR1.15 | Account email addresses are personal data: readable only by the account and by admins within reach; the find-account function reveals only accounts within the caller's reach (BR2.15, the account access table) | Policy tests per role, including a group admin looking up an address outside their group |
| NFR1.16 | Seed and test credentials stay out of tracked files (U1 scans) and the operator command refuses a non-local host unless the operator types it (BR2.18) | The existing scans plus the command tests |

| NFR1.22 | Reset and sign-in threats: a reset link works once and expires after 1 hour; opening the link with a GET does not consume it (the exchange is a POST); after a reset every other session of the account is ended; sign-in and reset requests for an unknown, a deactivated and an active address return the same status and body, and the response time difference is reported (target under 100 ms) (BR2.1, BR2.12) | Tests against the real stack: reuse, expiry with a controllable clock, GET versus POST, sessions after reset, and a three-address comparison of responses and timings |
| NFR1.23 | Invitation reach: a group admin cannot invite a super_admin or a role for another group, cannot revoke or resend invitations of another group, and a super admin of another organization cannot touch them (BR2.9) | Database tests per actor and per invitation action, with denied events asserted |
| NFR1.24 | Direct brute-force exposure through the sign-in service is quantified and accepted: at 30 requests per 5 minutes per source address an attacker with one address can make about 360 guesses per hour against one account; the app-side lockout does not stop this (it covers the app's screen only); this is recorded as an accepted risk of the owner's weaker password choice, to be revisited with the password-verification hook before any hosted use | A documented risk entry in the unit's checkpoint report; no test |

Threat considerations: token theft and reuse (NFR1.1, NFR1.7, NFR1.8), direct calls to the sign-in service (NFR1.1, NFR1.11, recorded lockout risk), privilege escalation through grant functions (NFR1.12), leaking existence or personal data (NFR1.13, NFR1.15), key leakage (NFR1.4, NFR1.5), and logging secrets (NFR1.6).
