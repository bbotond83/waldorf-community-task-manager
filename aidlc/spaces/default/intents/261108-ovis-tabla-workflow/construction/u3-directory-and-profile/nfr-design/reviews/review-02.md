> R-01 Reviewer note: The lock sequence is now stated: advisory key first, then family, parent, request, with the request recheck. The request step replaces the old pending row under the parent lock, so the partial unique index is never hit. Removal and confirmation share one order. Residual wording gaps are listed under New findings as Minor.

> R-02 Reviewer note: One advisory key, built from the hashed address, now covers add-parent, add-family, email edit on record, email request, email confirmation and the resend limit. It is taken first, in ascending order for two addresses, and every taken-address check returns EMAIL_UNAVAILABLE. Two steps that also write an address are missing from the list (see New findings, Minor).

> R-03 Reviewer note: The password-change audit is now recorded as a deviation in both `security-design.md` and `reliability-design.md`, with the reason and the accepted loss on a crash.

> R-04 Reviewer note: Both design files record "deleted, not cancelled", but `rules.md` (BR36.3, BR34.3), NFR1.5 and NFR7.1 still say "cancel". The NFR7.1 pass criterion "pending change cancelled" cannot be met by a deleted row. `traceability.json` does not carry the deviation.

> R-05 Reviewer note: Replay sends nothing and writes no row. The table has row-level security and no read. The rate check runs after the availability check. The wording of that last point is still confusing (see New findings).

> R-06 Reviewer note: EMAIL_RATE_LIMITED is in the refusal list of `observability-design.md`. The audit sentence now says "each command that changes data" and names the exceptions. Its refusal state (validation or retryable) is still not named.
