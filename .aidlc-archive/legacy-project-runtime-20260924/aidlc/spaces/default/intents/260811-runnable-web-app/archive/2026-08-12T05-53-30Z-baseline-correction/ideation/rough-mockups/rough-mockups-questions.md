## Q1. What is the primary entry point and screen structure?

- A. One task board page with header, task list, and always-visible creation form
- B. Dashboard landing page plus a separate task page
- C. Task list page with a creation modal
- D. Multi-page navigation across existing domain modules
- E. Not yet defined
- X. Other

[Answer]: A. One task board page with header, task list, and always-visible creation form

## Q2. What is the core happy path?

- A. Open app, scan seeded tasks, complete form, submit, see success and new task at the top
- B. Open app, navigate to tasks, open modal, create task, close modal
- C. Open app and browse tasks only
- D. Another flow defined in follow-up
- E. Not yet defined
- X. Other

[Answer]: A. Open app, scan seeded tasks, complete form, submit, see success and new task at the top

## Q3. What information hierarchy should the page use?

- A. Page purpose and status first, task list as primary content, creation form as supporting panel
- B. Creation form first, task list below
- C. Equal two-column emphasis
- D. Minimal hierarchy with only form and list labels
- E. Not yet defined
- X. Other

[Answer]: A. Page purpose and status first, task list as primary content, creation form as supporting panel

## Q4. What visual guidelines should the rough concept follow?

- E. Not yet defined
- X. Other

[Answer]: A. Warm, calm Waldorf-inspired palette with modern accessible components and no formal design-system dependency

## Q5. Which device sizes must be supported?
